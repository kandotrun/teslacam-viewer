# TeslaCam Viewer 設計

## 文書の状態

本設計は、2026年8月21日に承認された「イベント一覧と6カメラ同期シアター」を具体化する。

公開基盤にはHonoとCloudflare Workers Static Assetsを使用する。

クライアント、Worker、共有データモデルはTypeScriptで実装する。

## 目的

TeslaCamを保存したSSDをMacへ接続した利用者が、ブラウザから`TeslaCam`フォルダを選択し、Finder上のファイル一覧を意識せずに映像を確認できるようにする。

映像をセントリー、保存済み、最近の走行に分類し、同時刻の6カメラ映像を一つのイベントとして同期再生する。

選択した映像、ファイル名、メタデータはMac上だけで処理し、Cloudflare Workersを含む外部サーバーへ送信しない。

## 確認済みの入力

接続中のSSDには`RecentClips`、`SavedClips`、`SentryClips`、`EncryptedClips`が存在する。

再生対象の映像はH.264形式で、解像度は1448×938、フレームレートは24fps、長さは約1分である。

カメラ名は`front`、`back`、`left_pillar`、`left_repeater`、`right_pillar`、`right_repeater`の6種類である。

`RecentClips`では映像が直下に置かれ、ファイル名に撮影日時とカメラ名が含まれる。

`SavedClips`と`SentryClips`ではイベントごとのディレクトリに複数セグメント、`event.json`、`event.mp4`、`thumb.png`が置かれる。

実データにはカメラ映像が欠けたセグメントがあるため、6方向が揃わない状態を正常系として扱う。

## 対象範囲

初期版は次の機能を含む。

- `TeslaCam`フォルダまたは既知カテゴリのフォルダを選択する。
- セントリー、保存済み、最近の走行を自動分類する。
- 1分単位の映像をイベントとセグメントへ再構成する。
- 種類、日付、時刻でイベントを絞り込む。
- 6方向を同期再生する。
- 6画面表示と1画面拡大を切り替える。
- 再生、停止、10秒移動、シーク、速度変更、前後イベント移動を提供する。
- 欠損したカメラと再生できない映像を、イベント全体を止めずに表示する。
- セントリーの検知時刻を取得できた場合にタイムラインへ表示する。
- フォルダ走査の進捗と結果件数を表示する。
- Chrome系ブラウザのFile System Access APIと、ディレクトリ入力によるフォールバックを提供する。

初期版は次の機能を含まない。

- ログイン
- クラウド保存
- 映像共有
- 地図表示
- AIによる映像分類
- 映像編集と書き出し
- 注釈
- 暗号化された映像の復号

## システム構成

システムはCloudflare Worker、静的クライアント、ローカルファイル処理の三つに分ける。

### Cloudflare Worker

HonoをWorkerのHTTPエントリーポイントに使用する。

Honoは`/api/health`を提供し、デプロイ状態を機械的に検証できるようにする。

Reactのビルド成果物はWorkers Static Assetsとして同じデプロイ単位へ含める。

通常の静的アセットはWorkerを経由せずに配信し、`/api/*`だけをWorker優先ルートにする。

静的レスポンスのセキュリティヘッダーは`_headers`で設定し、Honoが返すレスポンスには同じ方針のヘッダーをミドルウェアで付与する。

WorkerはTeslaCamの映像、ディレクトリ一覧、メタデータを受信するAPIを持たない。

### 静的クライアント

ReactとTypeScriptをViteでビルドする。

クライアントはフォルダ選択、走査、イベント構築、一覧表示、再生制御を担当する。

状態はイベント操作から明示的に更新し、`useEffect`はメディア要素のライフサイクル管理など、イベントハンドラーだけでは複雑になる箇所に限定する。

選択中のイベント以外の動画にはBlob URLを作らない。

### ローカルファイル処理

ChromeとEdgeでは`showDirectoryPicker()`を利用する。

未対応ブラウザでは`<input type="file" webkitdirectory>`を利用し、`webkitRelativePath`から相対パスを復元する。

二つの入力方式は共通のファイル記述型へ変換し、それ以降のパーサーとUIから差を隠す。

フォルダ走査中はファイル名と小さなJSONだけを読み、映像本体は再生時まで読み込まない。

## 型設計

外部入力は検証前の値として受け取り、Zodスキーマを通過した値だけをアプリケーション型へ変換する。

`event.json`は既知フィールドを文字列として検証し、未知フィールドが追加されてもイベント全体を破棄しない。

カテゴリは`recent`、`saved`、`sentry`のリテラル共用体で表す。

カメラは6種類のリテラル共用体で表し、画面上の並び順を一つの定数で管理する。

走査結果は、成功、部分成功、非対応フォルダ、権限拒否、読み込み中断を判別可能な共用体で表す。

再生タイルは、再生可能、欠損、破損、コーデック非対応を判別可能な共用体で表す。

CloudflareのBindings型は`wrangler types`で生成し、手書きの`Env`型を置かない。

`any`、`as any`、二重キャスト、TypeScriptの診断抑制は使用しない。

## イベント構築

### 保存済みとセントリー

`SavedClips`と`SentryClips`では、直下のイベントディレクトリを一つのイベントとして扱う。

各イベント内で撮影日時とカメラ名をファイル名から抽出し、同じ撮影日時を一つのセグメントへまとめる。

各カメラのセグメントはファイル名の日時順に並べる。

`event.mp4`は代表映像として保持するが、6カメラ表示では個別カメラの映像を優先する。

`thumb.png`が存在する場合はイベント一覧のサムネイルに使用する。

`event.json`の検知時刻がイベント範囲内にある場合は、タイムラインの検知マーカーへ変換する。

住所と推定座標は初期版の画面へ表示せず、外部ログにも出力しない。

### 最近の走行

`RecentClips`では、同じ撮影日時を持つカメラ映像を一つのセグメントへまとめる。

連続するセグメントの開始時刻の差が90秒以内なら、同じ走行イベントへ連結する。

90秒を超える空白があれば、新しい走行イベントを開始する。

日付をまたいでも時間差が90秒以内なら同じ走行イベントとして扱い、一覧上の日付には開始日時を使用する。

### 不完全な入力

未知のファイル、0バイトの映像、認識できないカメラ名は再生対象から除外し、走査結果に件数を残す。

一部のカメラが欠けていても、存在するカメラだけでイベントを構築する。

既知カテゴリが一つも見つからない場合だけ、選択フォルダがTeslaCamではないと判断する。

`EncryptedClips`にファイルがある場合は件数だけを示し、再生は試みない。

## 同期再生

イベント全体の経過秒を共有再生位置として管理する。

各カメラの現在セグメントとセグメント内再生位置は、共有再生位置から計算する。

再生、停止、シーク、速度変更はすべての再生可能なカメラへ同じ操作として適用する。

拡大表示中も共有再生位置を維持し、グリッドへ戻したときに同じ位置から再開する。

カメラ間の再生位置が250ミリ秒を超えてずれた場合にだけ補正し、毎フレームのシークによる映像の乱れを避ける。

セグメント境界では次のBlob URLを遅延生成し、各カメラを同じ共有再生位置へ移す。

イベント切り替え時と画面離脱時に、作成済みのBlob URLをすべて解放する。

## 画面設計

### フォルダ未選択画面

画面中央に「TeslaCamフォルダを選ぶ」を唯一の主操作として配置する。

「選択した映像はブラウザ内だけで処理され、外部へ送信されません」と常時表示する。

対応ブラウザ、選択すべきフォルダ、処理対象カテゴリを短く説明する。

### 閲覧画面

大画面では、カテゴリ、イベント一覧、再生領域の3ペインを使用する。

カテゴリペインには、すべて、セントリー、保存済み、最近の走行を表示する。

イベント一覧にはサムネイル、日時、長さ、利用可能なカメラ数、欠損状態を表示する。

再生領域は車両の位置関係を意識した2行3列とし、すべてのタイルに日本語のカメラ名を表示する。

カメラタイルを選択すると1画面へ拡大し、Escapeキーまたは表示切り替え操作でグリッドへ戻る。

再生領域の下に共有タイムライン、再生操作、速度、イベント移動を置く。

ヘッダーにはフォルダ名、別フォルダの選択、再走査、ローカル処理バッジを表示する。

### レスポンシブ表示

中画面ではカテゴリを上部タブへ移し、イベント一覧を開閉式にする。

小画面では1カメラ表示を既定とし、カメラ名を横スクロールできる切り替えとして表示する。

フォルダ選択が利用できないモバイル環境では、PC版ChromeまたはEdgeで開く案内を表示する。

### 視覚設計

背景は映像を見分けやすいチャコール系とする。

セントリーには赤、保存済みには青、最近の走行には低彩度のニュートラル色を使用する。

色だけに意味を持たせず、ラベルとアイコンを併用する。

Tesla公式UIやロゴを模倣せず、映像確認ツールとして独立した外観にする。

## 操作とアクセシビリティ

Spaceキーで再生と停止を切り替える。

左右矢印キーで10秒移動する。

数字キー1から6でカメラを選択する。

Escapeキーで1画面表示からグリッドへ戻る。

すべての操作をキーボードだけで実行できるようにし、フォーカス状態を明示する。

タップ領域は44ピクセル以上とする。

読み込み進捗と再生エラーはライブ領域で通知する。

`prefers-reduced-motion`を尊重し、状態の理解に不要なアニメーションを行わない。

## エラー表示

アクセス拒否では、権限が与えられなかったことと再選択方法を示す。

誤ったフォルダでは、`SentryClips`などを含む`TeslaCam`フォルダを選ぶよう案内する。

空のカテゴリは異常扱いせず、「この種類のイベントはありません」と表示する。

欠損カメラは該当タイルだけを「このカメラ映像はありません」と表示する。

破損または再生非対応の映像は件数を示し、利用可能な映像の操作を継続できるようにする。

SSDが取り外された場合は読み込み失敗として通知し、再接続と再選択を案内する。

## セキュリティとプライバシー

`Content-Security-Policy`では、スクリプト、接続、画像、動画の送信先を同一オリジンとBlob URLへ限定する。

`connect-src 'self'`を設定し、クライアントコードから任意の外部ホストへ接続できないようにする。

`media-src 'self' blob:`と`img-src 'self' blob: data:`を許可し、ローカル映像とサムネイルだけを表示できるようにする。

`frame-ancestors 'none'`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、権限を制限した`Permissions-Policy`を設定する。

アクセス解析、外部フォント、外部画像、エラー収集SDKを組み込まない。

映像、Blob、メタデータ、位置情報をLocal Storage、IndexedDB、Cache Storageへ保存しない。

フォルダハンドルは永続化せず、再訪時は利用者が改めて選択する。

コンソールとWorkerログにはローカルファイル名、日時、住所、座標を記録しない。

## Cloudflare設定

設定ファイルには`wrangler.jsonc`を使用する。

`compatibility_date`には実装日の2026年8月21日を使用する。

Node.js互換機能を必要とする依存関係に備えて`nodejs_compat`を有効にする。

Bindings型は設定ファイルから生成し、型生成結果が最新であることをCIで検証する。

静的アセットは`dist`から配信し、未解決パスはSPAの`index.html`へフォールバックする。

Worker優先ルートは`/api/*`に限定する。

本番WorkerのCustom Domainには`teslacam.2-38.com`を設定する。

Cloudflareの観測機能を有効にするが、Workerが扱うのは公開アプリのHTTP情報だけであり、ローカル映像情報はWorkerへ到達しない。

## 検証方針

パーサーの単体テストでは、実映像を使わず、合成したファイル名とJSONでカテゴリ、イベント、セグメント、カメラ欠損を検証する。

Workerのテストでは、Honoの`app.request()`を使ってヘルスチェック、存在しないAPI、セキュリティヘッダーを検証する。

コンポーネントテストでは、未選択、走査中、一覧、欠損、再生エラーの表示を検証する。

ブラウザテストでは、公開可能な短い合成動画だけを使ってフォルダ選択のフォールバック、イベント選択、再生操作、カメラ切り替えを検証する。

実機確認では接続中のSSDを使用し、実映像やフレームをテスト成果物へ保存しない。

Chrome系ブラウザでFile System Access APIから走査と再生を確認する。

Safariではディレクトリ入力のフォールバックから走査と再生を確認する。

開発者ツールのNetwork記録で、ローカル動画がHTTP送信されていないことを確認する。

TypeScript、ESLint、Vitest、ビルド、Workerのドライラン、Playwright、視覚QAを完了条件とする。

## 受け入れ条件

- `teslacam.2-38.com`がHTTPSで表示される。
- フォルダ選択操作から接続中の`TeslaCam`を開ける。
- 3カテゴリを自動分類し、イベント件数を表示できる。
- 保存済みとセントリーをイベントディレクトリ単位で表示できる。
- 最近の走行を連続セグメント単位で表示できる。
- 同じイベントの6カメラを同期再生できる。
- 欠損したカメラがあっても残りの映像を再生できる。
- グリッドと1画面表示を切り替えられる。
- 再生、停止、10秒移動、シーク、速度変更、前後イベント移動が動作する。
- イベント切り替え後に不要なBlob URLが解放される。
- 選択した動画、ファイル名、位置情報が外部へ送信されない。
- 実際のTeslaCam映像、サムネイル、メタデータをGitへ含めない。
- TypeScriptで`any`を使用せず、型検査、テスト、ビルドが成功する。
- HonoのヘルスチェックとWorkers Static Assetsが同じWorkerとして動作する。
- GitHubの`main`が公開中のソースと一致する。
